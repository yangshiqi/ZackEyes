# Demo mode Implementation Plan

> **For agentic workers:** Execute this approved plan inline with executing-plans and test-driven-development. Review the completed change against the originating issue and repository standards.

**Goal:** Show a clearly marked, interactive synthetic Claude/Codex fleet with one-click exit and complete separation from live ingestion.

**Architecture:** A DemoSessionController owns an ephemeral SessionStore. NotchViewModel chooses a presentationStore while AppDelegate retains its original live store; real attention stops demo automatically.

**Tech Stack:** Swift 6, Foundation, Combine, SwiftUI, AppKit; no dependencies.

**Spec:** docs/superpowers/specs/2026-10-14-demo-mode-design.md

## Global Constraints

- macOS 14 minimum; preserve nonactivating panel and mouse/visibility behavior.
- Never read or write Codex config.toml. No synthetic Bridge events, CLI calls, user config changes, notifications, journal entries or quota cache writes.
- Global quota readings remain live; mode is ephemeral; real attention interrupts demo.
